Supervised agentic pentesting that produces proof, not prose.

Violin is an open-source Hermes Agent profile for authorised penetration tests. Every target-touching command passes a required execution guard, every command returns a signed receipt, and every finding must bind to the receipt that proves it.

Before a target command runs

Seven checks, one boundary — violin_exec.

  1. Written authorisation in scope.yaml
  2. Approved scope match for the resolved target
  3. Active PTT task under the current phase
  4. Routed specialist skill bound to the task
  5. Hypothesis binding for the command
  6. Command history and synchronisation state
  7. Engagement gates — fail closed
A passing command returns a signed execution receipt. A finding without one is not a finding.

The trust problem

An agent that finds real vulnerabilities is not the hard part any more. The hard part is answering three questions a client, an auditor, or your own team will ask: did it stay in scope, can you prove the finding, and can you resume the engagement tomorrow?

Is it in scope?

Scope, phase, active PTT task, routed skill, hypothesis binding, and command history are all checked before a target command is allowed to start. Gates fail closed.

Can you prove it?

Each execution returns a signed receipt. A finding is only accepted when it binds to receipts that authenticate the decisive request and response bytes.

Can you resume it?

PTT tasks, hypotheses, checkpoints, evidence, and reports live in engagement state on disk, so context compression does not reset the assessment.

Stated plainly: the guard is an execution-boundary control, not network containment. Violin documents this instead of implying otherwise — read the safety model and the benchmark limits before you point it at anything. Use it only against systems you own or are written-authorised to test.

Eleven registered tools

One typed registry, no tool-specific execution adapters, no target allowlists. The violin_exec boundary is the same for every installed non-interactive tool.

Honest limits

Promotional pages usually skip this section. Violin's own documentation does not.

A single run is a noisy sample

Agentic runs vary run to run. The project reports a distribution — mean pass@1, pass@k, pass^k — and prefers the mean over the best run. A repo test pass is not a live benchmark score.

The guard is not containment

The raw-terminal hook is a best-effort safety net. Network-level containment is your environment's job, not the profile's.

No model choices baked in

Violin adds no credentials and selects no model or provider; it inherits whatever Hermes is configured with.

Human validation stays

Receipts prove what the tool saw and sent. They do not replace a human judgement call on severity, impact, or whether a finding is worth reporting.

Quick start

Requirements: Hermes Agent 0.18.0+, a Kali Linux or Parrot OS tool environment, Python 3.11 and uv for local development, and written authorisation with an approved scope.

hermes profile install https://github.com/Strategic-Automation/violin
hermes -p violin

# then, in the session:
Run an authorized penetration test against example.com.

Violin collects scope before any target interaction. Read the engagement lifecycle and the benchmark methodology before your first run.
